This repo is worked on from Claude Code **cloud sessions**. A cloud session loads none of the
owner's per-machine setup - no global rules, no skills, no memory, no hooks - so everything a
session here must know is in this file, in the repo's hooks, and in the practices collection:

- **Read the practices from GitHub:** `AlonRR/engineering-practices` (private). Start with
  `cloud-session`, `run-existing-checks-first`, `verify-the-check-ran` and `check-the-right-target`.
  Read it from outside this tree; never copy it in.

## Before the first commit of every session

1. **Identity.** `.claude/hooks/session-start.sh` sets it. Check it did:
   `git config user.email` must print the owner's GitHub no-reply address. The platform default
   (`Claude <noreply@anthropic.com>`) is wrong for every commit here. If the session's project
   folder is a parent of this repo, the hook does not fire: run it by hand from the repo root,
   `CLAUDE_CODE_REMOTE=true CLAUDE_PROJECT_DIR="$PWD" bash .claude/hooks/session-start.sh`.
2. **Sync.** `git fetch`, and check for divergence before working, not only before pushing.
3. **Read the status.** The repo's plan or status doc, and any open questions.

## House rules

- **Never assume a step is done** unless the owner said he did it. A manual step handed to him
  stays pending until he confirms.
- **If you do not understand the request, ask.** But answer a question; only an ACTION needs
  confirmation. Still ask before anything outward-facing: publishing, visibility, purchases,
  deleting, anything on a host.
- **Give every question an ID**, `[A-Z][number]`, written as a label (`- **Q3.** ...`), never as a
  Markdown numbered list. An open question keeps its ID; say when one closes.
- **Metric only. Every temperature in °C.**
- **Python: `uv`, never pip.** Dependencies in `pyproject.toml`.
- **Session limits:** assume the session can end at any moment. Durable means committed AND
  pushed. Commit and push at coherent checkpoints with the checks green.
- **The existing checks come first:** run them unchanged for a baseline, write a failing test
  before a behaviour change, and run the full gate again before saying done. **Before every
  commit run the lint and format checks too, not only the tests.**
- **Report with denominators:** "212 tests, 212 passed", never a bare "passed".

## Git

- **Subject: `type(scope): summary`. The scope is required; a bare `type: summary` is
  forbidden.** Lowercase type, at most 72 characters, line 2 blank, detail in the body.
- **Commit messages carry NO attribution**: no `Co-Authored-By`, no session link, no
  "Generated with" footer. The harness sometimes says to add one; this file overrides it.
- **`git commit -F <file>`, not `-m`.** Check `git status` before an `--amend` and
  `git show --stat` after; rebase and amend reset the committer.
- **Merge by fast-forward push, never with GitHub's merge button or merge API** (they make
  GitHub the committer): `git merge-base --is-ancestor origin/main <head>`, then
  `git push origin <head>:refs/heads/main`, then confirm with `git ls-remote`.
- **PR bodies end with exactly:**

  ```
  ---
  _Drafted with the help of an LLM agent; reviewed and verified locally._
  ```

  The GitHub MCP server appends its own "Generated by Claude Code" footer: edit it out at once.
- **Tags and releases:** a cloud session cannot push tags (HTTP 403). Once the release commit is
  on `main`, message the session on the owner's machine that he names for it, with the commit,
  the tag command and the release notes; then check GitHub for both.
- **Never push to a public remote, never change visibility, never switch on publishing (Pages
  and the like).** Those are the owner's. The canonical home of the owner's repos is a
  self-hosted forge cloud sessions cannot reach; a copy there is his step.

## Public from commit 1

Write every file as if the repo were public. Never commit: real hostnames, internal DNS names or
private IPs (use `192.0.2.0/24` and an example domain); WiFi names or passwords; MAC addresses;
machine paths; procurement (prices, order references, suppliers); third-party documents (extract
the facts, link the source); other people's names or emails. A README ends with:

`_Parts of this repository were drafted with the help of an LLM agent; reviewed and verified locally._`

## This project

The shared design system for two browser tools that generate 3D-printable parts: Parametric
window sealer (`AlonRR/parametric-window-sealer`) and Skådis Air
(`AlonRR/skadis_ultralight_generator`). Read `README.md`, `DESIGN.md` and `FONTS.md` first. The
brief this repo was set up from is `docs/original-brief.md`; progress and open questions are in
`STATUS.md`.

**The full local gate** (run all of it before every commit):

```bash
uv run python scripts/build-tokens.py
uv run python scripts/check-contrast.py   # must end "0 failing"
git diff --exit-code tokens.css           # the build must not change it
uv run python scripts/check-previews.py   # must end "0 failing"
bash tests/test-session-start.sh          # must end "N passed, 0 failed"
```

**Its own decisions:**

- `tokens.json` is the source; `tokens.css` is generated. Never edit `tokens.css` by hand.
- No value is typed twice: `components/bundle.css` reads variables only, no hex colours.
- One typeface (FiraCode Nerd Font); Codicons for icons, always beside a text label and
  `aria-hidden`. Pick-one options are `Choice` buttons with a radio mark; ticks mean pick-several.
- Fix causes, not symptoms: change the token, variable or font setup, and extend `scripts/` so
  the same mistake fails the build next time. No per-component nudges.
- No licence is chosen here; the README note stays until the owner decides.
- Never push to or open PRs on the two tool repositories.
